## 新得到的失败证据与修正

1. MySQL 默认 REPEATABLE READ 下，仅加授权行锁仍使同一刷新凭据的 8 个并发请求全部成功。
   改为 READ COMMITTED，并在账号锁和授权锁内重新查询，避免消费旧快照。
2. 完整安全链中，新增 Provider 抛出拒绝异常后，ProviderManager 会继续尝试默认 Provider。
   直接追加 Provider 使默认刷新绕过自定义到期检查。现改为按客户端路由到唯一适用实现，保留其他客户端的原生实现。
3. 只查询当前 status 不能阻止解冻后恢复旧授权。新增最小持久安全版本，
   由用户更新触发器递增，并在账号加载、授权创建、刷新和访问时核对 userId 与版本。
4. 公共客户端不能原样通过默认客户端认证调用撤销端点。扩展仅识别目标公共客户端，
   仍由现有撤销 Provider 验证凭据绑定并撤销授权。
5. 依据 [RFC 9700 §4.14.2](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14.2)，
   旧刷新凭据重放必须使同一授权的当前凭据一并失效。候选使用最小的已消费凭据摘要记录完成此检查，
   沿用 OAuth 授权作为会话，不新增用户表。
6. Sol 双轴复核发现公共客户端转换器可被用于 `/oauth2/introspect`。
   HTTP 复现实测在刷新参数注入时返回 200；现已前置限制公共客户端只能认证精确 POST token/revoke 入口，
   刷新参数和有效 PKCE code 两种查询尝试均返回 401，两位 Sol 回看确认问题关闭。
7. 补查发现其他客户端签发的旧 CUSTOMER 主体可以绕过仅针对桌面授权的版本验证。
   现于新增私有接口统一核对主体 userId 和安全版本。原生机密客户端换码/刷新对照复现旧 Token 返回 200，
   修复后改密、旧主体刷新和用户名复用均返回 401，使用最新账号资料构建的主体返回 200；
   实际密码登录仍未联调，Spec Sol 回看确认当前边界问题关闭。

## 验证边界

JUnit 5 测试使用项目真实 Ballcat 1.4.2 / SAS 0.4.2 依赖和实际 MySQL 持久层。
测试通过与应用一致的 EnableOauth2AuthorizationServer / EnableOauth2ResourceServer 注解装配安全链，
MockMvc 发起 HTTP 语义的 Servlet 请求；授权码与账号是隔离夹具，不启动完整业务应用。

数据库连接信息来自本地开发配置，仅用于在本机服务创建随机专用测试库；复制空 sys_user 结构，
加载 SAS 原生授权表与候选迁移。测试后删除该测试库，未写真实账号或客户端配置；未使用 Redis。

覆盖无共享密钥换码/轮换、PKCE 和回调校验、重放、并发刷新、scope 越权、固定 30 天窗口、
授权服务重建、冻结/解冻、改密/重置、退出、刷新凭据不能访问资源，以及账号归属绑定。
30 天使用可控时钟覆盖，并不代表已经运行 30 天。

最终定向结果：**36 项，0 failures / errors / skipped**（边界 4、已有兼容性探针 11、真实 JDBC 安全链 21）。
JDBC 用例约 59 秒，包含每个用例独立建库、迁移、删库；Java 编译、定向格式校验和 WAR 打包均通过。
已有兼容性探针原先已暂存，本次不夹带提交，保留用户工作。

扩展安全测试执行过 221 项，2 failures、0 errors、8 skipped。排除会写真实 OAuth 配置的初始化测试，
以及会启动完整业务应用的 MythicShopServiceImplTest；两个失败来自未修改的 LolServiceImplTest，
单独运行仍失败（字典保存次数的旧断言与当前 18 个类别不符）。复核修复后只按影响范围重跑鉴权测试，
最终 36 项与 WAR 构建均通过；没有把扩展集描述为全绿。
