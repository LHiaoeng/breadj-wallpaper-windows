## 1. 需求与结论

将 `light-shadow-wallpaper-client-admin` 管理的壁纸，通过 API 展示在当前 Windows 壁纸客户端中，使用户无需打开管理后台即可浏览图片和视频壁纸。

已核实的数据链路是：管理前端维护数据 → `light-shadow-wallpaper-admin` 后端保存并提供开放接口 → Windows 客户端读取元数据 → 根据资源 URL 加载封面和预览。

推荐复用后端已有 `/rest/wallpaper` 接口，在 Windows 客户端提供独立的“在线壁纸”入口。现有 Lively 图库的认证、订阅及 ZIP 安装契约与该后端不同，不能仅替换服务器地址。

本次交付为需求文档，不包含功能实现或生产接口联调。本文“已核实”指本机源码或可读取历史记录；所有性能目标、交互细节和分期均为本次建议，不能视为历史已经确认的决策。

## 3. 当前系统事实

### 3.1 三个项目的职责

| 项目 | 当前职责 | 本次关联 |
| --- | --- | --- |
| `light-shadow-wallpaper-client-admin` | Vue/TypeScript 管理前端；使用 `/wallpaper/wallpaper/page` 等管理接口 | 数据维护入口，不直接作为 Windows API 服务 |
| `light-shadow-wallpaper-admin` | Java 后端；提供管理接口及 `/rest/wallpaper` 开放接口 | Windows 读取壁纸的服务端 |
| `breadj-wallpaper-windows` | 基于 Lively 的 Windows 应用，已有 WinUI 页面、图库、本地库及播放核心 | 增加在线数据读取和展示 |

### 3.2 已存在的能力与限制

- 开放分页返回 `R<PageResult<WallpaperRestVO>>`；前端公共类型定义对应 `{ code, message, data: { records, total } }`。
- 后端配置包含 `/rest/**` 放行项；目标部署是否有网关认证、防盗链等额外限制尚未验证。
- 通用开放列表在服务端固定筛选 `status=0`，同时要求 `url` 非空。管理列表与公开列表数量可能不同。
- 通用列表实际按 `id DESC`、`launchTime DESC` 排序，不能称为严格按上架时间最新排序。
- `type=1` 表示图片，`type=2` 表示视频；`status=0` 表示启用，`status=1` 表示停用。
- 返回值包含 `urlBackup` 和 `posterBackup`，但仅存在备用 URL、主 `url` 为空的数据仍会被当前公开列表过滤。
- 当前 `GalleryClient` 使用 Lively 的用户、认证、订阅及 `gallery/{id}/download` 接口。
- `GalleryViewModel` 初始化依赖登录；`LibraryViewModel.AddWallpaperGallery` 先订阅再下载 ZIP。该流程不能直接承接单个图片或视频 URL。
- 本地库已有文件导入及壁纸设置能力，可作为后续下载闭环的复用基础；本文未验证实际媒体播放兼容性。

## 4. 用户与成功标准

主要用户为 Windows 桌面壁纸使用者；管理人员继续在现有后台维护内容。

首期成功标准：用户打开“在线壁纸”，能看到后端允许公开的真实数据，能按标题和类型查找，能查看预览及来源；分页、错误、空结果均有明确反馈，且不会影响当前正在运行的桌面壁纸。

管理侧启用、停用或修改内容后，在用户下次成功刷新列表时反映最新结果，不要求推送或实时同步。

| 优先级 | 内容 | 交付判断 |
| --- | --- | --- |
| P0：首期 | 在线入口、分页列表、标题搜索、图片/视频筛选、详情预览、来源展示、刷新与异常状态 | 满足当前“通过 API 显示”诉求 |

## 6. P0 产品要求

### 6.1 页面入口与浏览

建议在主导航增加“在线壁纸”，保留现有本地壁纸库。页面沿用当前 WinUI 风格和主题。

顶部依次提供：标题搜索框、类型选择（全部/图片/视频）、刷新。主体为随窗口宽度调整列数的封面卡片列表；卡片显示封面、标题、图片/视频标记。来源在详情中显示，列表可在空间允许时显示。

首次进入显示加载占位，默认请求全部类型的第一页，建议每页 20 条。滚动到尾部加载下一页，同时只允许一个相同条件的分页请求在途。

分页规则：成功后才推进页码；失败后停留原页并显示重试；按服务端 ID 去重；以原始已返回记录数与 `total`、空页共同判断结束，不能使用去重后的卡片数量判断是否还有下一页。重刷恢复第一页。

### 6.2 搜索、筛选和刷新

- 标题搜索按 Enter 或搜索按钮提交，首期不要求输入即搜索。
- 改变类型或搜索条件时，清空旧查询的分页状态并加载第一页。
- 取消或忽略过期请求，较早请求不能覆盖较新的搜索结果。
- “全部”不发送 `type`，图片发送 `1`，视频发送 `2`。
- 首期保持后端默认排序，不提供尚未验证的热门、随机或多种排序选项。
- 刷新当前查询时可保留旧列表，失败提示“刷新失败，当前为上次结果”；不得把失败显示为“暂无壁纸”。

### 6.3 封面与详情

点击卡片打开详情面板或详情页，展示标题、媒体类型、预览、描述、来源、版权信息、上架时间，以及有效的原始来源链接。

图片优先使用海报作为列表封面，无海报可使用图片资源；视频必须使用海报或占位图，列表不自动播放视频。进入详情后由用户主动点击播放，默认静音；离开详情停止播放并释放资源。

标题缺失显示“未命名壁纸”；描述、版权、日期等可选字段缺失时隐藏对应项。未知来源显示“其他来源”，不猜测含义。未知媒体类型可显示基础信息，但禁用预览并注明暂不支持。

仅按纯文本显示描述，外部链接使用系统浏览器打开。封面失败只影响对应卡片；资源预览失败保留元数据并允许重试。

### 6.4 资源选择规则（建议）

媒体资源候选顺序：非空 `urlBackup` → 非空 `url`。海报候选顺序：非空 `posterBackup` → 非空 `poster`。相同 URL 去重；失败时每个候选最多尝试一次，并记录实际失败原因。

`urlBase` 在现有模型中不能确定为可直接下载的文件地址，不参与自动兜底。不根据扩展名、参数或域名擅自拼接高清地址。

生产资源只接受受支持的 HTTP(S) 媒体地址，优先 HTTPS；不将 API 下发的本地路径、自定义协议或可执行文件作为壁纸运行。实际可访问域名和 HTTP 遗留资源处理应在联调时确认。

### 6.5 页面状态

| 状态 | 展示与操作 |
| --- | --- |
| 首次加载 | 加载占位，可继续使用应用其他功能 |
| 加载成功且为空 | “暂无符合条件的壁纸”，提供清除筛选 |
| 无网络/超时 | “连接失败”，提供重试；已有内容保留 |
| HTTP 或业务失败 | 明确失败提示，不显示假空列表 |
| 下一页失败 | 保留已加载卡片，底部提供重试 |
| 数据格式错误 | 提示服务数据异常，记录字段问题 |
| 单条缺少 ID | 不生成可操作卡片，记录异常；同页有效项继续显示 |
| 封面/媒体失效 | 卡片占位或详情失败提示，允许重试 |
| 列表结束 | 显示“没有更多了”，不重复请求 |

## 7. API 对接要求

### 7.1 已有接口

以下为源码路由，不代表生产部署地址已经确认。

| 方法与路径 | 用途 | 分期 |
| --- | --- | --- |
| `GET /rest/wallpaper/page` | 通用壁纸分页 | P0 |
| `GET /rest/wallpaper/bing/page` | 必应专题分页 | P2 |
| `GET /rest/wallpaper/bing/regions` | 必应地区选项 | P2 |
| `GET /rest/wallpaper/spotlight/page` | Windows 聚焦专题分页 | P2 |
| `GET /rest/wallpaper/spotlight/regions` | 聚焦地区选项 | P2 |
| `GET /rest/wallpaper/getRandomWallpaper` | 随机壁纸 | P2 |
| `GET /rest/wallpaper/getNextWallpaper` | 下一张 | P2 |
| `GET /rest/wallpaper/getPreviousWallpaper` | 上一张 | P2 |
| `PATCH /rest/wallpaper/incrementUsage/{wallpaperId}` | 使用次数计数 | P2 |

P0 详情复用列表记录，不假设后端已存在 `/rest/wallpaper/{id}` 详情接口。未来若要在下载前刷新单条资源或严格验证下架状态，应明确补充详情/可用性接口。

### 7.2 请求与响应

请求示意：`GET {API_BASE_URL}/rest/wallpaper/page?current=1&size=20&type=1&title={URL编码后的标题}`。

`API_BASE_URL` 为部署配置，不使用管理前端域名或 Vite `/api` 代理地址推断。`current`、`size` 来自现有分页类型；页码从 1 开始的约定和服务端分页上限需在真实接口样例中确认。

响应示意（结构基于代码，数据为说明用示例）：

```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "records": [
      {
        "id": 123,
        "type": 1,
        "title": "示例壁纸",
        "url": "https://media.example.com/wallpaper.jpg",
        "poster": "https://media.example.com/poster.jpg",
        "urlBackup": null,
        "posterBackup": null,
        "source": 2,
        "description": "示例描述"
      }
    ],
    "total": 1
  }
}
```

客户端同时检查 HTTP 状态和业务 `code`。历史样例成功码为 200，联调应再次确认；`data` 或 `records` 缺失属于格式异常，只有合法 `records: []` 才是空结果。解包在 API 层统一完成，页面不重复解包。

### 7.3 字段映射

| 后端字段 | 客户端含义 | 约束 |
| --- | --- | --- |
| `id` | 远端资源 ID | 接受 JSON 整数或十进制字符串，内部无损保存；不经浮点数转换 |
| `type` | 图片/视频 | 显式映射 1、2；不能直接强转 Lively 枚举 |
| `title` | 标题 | 可为空，有显示兜底 |
| `description` | 简介 | 纯文本，可为空 |
| `url` / `urlBackup` | 媒体候选地址 | 与海报分开处理 |
| `poster` / `posterBackup` | 海报候选地址 | 缺失或失败不阻断整个列表 |
| `source` | 内容来源编码 | 不复用为媒体类型；枚举清单待确认 |
| `titleLink` | 原内容链接 | 合法 HTTP(S) 地址才提供入口 |
| `copyright` / `copyrightLink` | 版权署名和链接 | 不将版权文本伪装成作者账号 |
| `launchTime` | 上架时间 | 后端为无时区 LocalDateTime，未确认时区前不做 UTC 换算 |
| `bingCountry` | 地区 | 首期详情可显示；专题筛选后续使用 |
| `urlBase` | 源站标识/基础地址字段 | 保留原值，不自动作为媒体地址 |

## 8. P1 下载与设置桌面（建议范围）

用户可选择“下载到本地”或“下载并设为壁纸”；已下载资源展示“设为壁纸”。下载完成不自动改变桌面，除非本次动作明确包含设置壁纸。

流程为：检查本地是否已有 → 下载到临时文件 → 验证媒体可用 → 导入本地库 → 持久化远端关联 → 按用户动作调用现有设置壁纸能力。

状态为“未下载 → 下载中 → 导入中 → 已下载”；失败和取消为明确的可重试状态。提供进度、取消、失败重试；未知文件长度显示不确定进度，不能伪造百分比。

后续实现约束：

1. 每个资源以“服务标识 + 远端 ID”确定唯一身份，避免与 Lively 原图库 ID 冲突；内部格式需兼容 Windows 文件名，不能直接用冒号作为目录名。
2. 同一资源的重复点击复用正在进行的任务，不创建重复下载；重启后检查真实本地文件再显示“已下载”。
3. 通过独立媒体导入流程复用本地库能力，不能把 MP4/JPG 当作现有图库 ZIP 解压。
4. 根据已验证的实际媒体类型映射 `WallpaperType.picture` / `WallpaperType.video`，生成或补充本地元数据及来源关系。
5. 磁盘不足、媒体损坏、下载中断和导入失败均不能留下“已下载”假状态；中断后的临时文件可清理，首期后续闭环不承诺断点续传。
6. 设置桌面成功以现有桌面核心返回状态为准，不能以下载完成代替；多屏选择沿用现有交互。
7. 删除本地资源同步清除安装状态；服务端停用不主动删除用户本地文件。严格即时下架限制需另外设计，当前仅保证刷新后从在线列表移除。
8. 使用次数统计不阻塞设置桌面；若实施，定义为设置成功后上报，不在预览和下载时上报。现有计数 API 未见幂等参数，不对不确定的写请求自动重试。

## 9. 非功能要求（建议验收目标）

- 以约定验收机、20 条首屏、正常测试网络为基准，首屏可操作内容目标在 3 秒内出现；该目标未测量，不包含视频完整下载。
- 列表、图片加载和网络请求不得阻塞 UI；缩略图按需加载，列表不预下载完整视频。
- 元数据请求建议 15 秒超时；用户可以立即手动重试。首期不承诺后台无限重试。
- 缩略图缓存设置容量上限并可淘汰；P0 断网保留已显示的内容，不承诺重启后完整离线在线图库。
- 日志包含请求路径、HTTP/业务状态、耗时和资源 ID，隐藏 Token、签名查询参数等敏感内容。
- API 地址按环境配置，Windows 安装包不内置后台管理员账号或对象存储密钥。
- 支持应用现有深浅主题、窗口缩放、键盘焦点与可读的按钮文字。

## 10. 实现边界与改动位置

推荐增加专用 API 服务、传输模型和在线页面 ViewModel，将网络解析、资源选择和界面状态分离。本文中的新增名称为建议，不表示文件已经存在。

| 区域 | 建议工作 |
| --- | --- |
| `Lively.UI.WinUI` | 增加在线入口、列表/详情视图及服务注册 |
| `Lively.UI.Shared` | 增加在线壁纸 ViewModel，负责查询状态和交互 |
| API 客户端层 | 增加 `LightShadowWallpaperClient`，处理响应解包、分页和取消 |
| 模型层 | 增加 `WallpaperRestDto` 与展示模型，显式映射类型及 ID |
| 本地库流程 | P1 增加普通媒体下载导入衔接与远端身份持久化 |
| Java 后端 | P0 优先复用现有接口，仅对联调证明的契约缺口做修改 |

不把 Lively 原有 Google/GitHub 登录、订阅列表、上传接口作为首期依赖。建议独立入口是为了使当前公开浏览需求可以落地；是否最终替换原图库入口属于待定产品选择。

| A08 | 视频详情预览 | 列表不播放；点击后可预览，退出后停止 |
| A09 | 海报缺失、备用地址失败 | 单卡片占位；按规则切换一次，不无限请求 |
| A10 | 后台停用后刷新 | 该记录从公开列表移除；不要求总量与管理后台完全一致 |
| A11 | 无网络、刷新失败 | 明确提示并允许重试，已显示内容保留 |

| B01 | P1 下载并设置图片/视频 | 文件有效、进入本地库、目标屏幕成功应用 |
| B02 | P1 取消、磁盘不足、导入失败 | 无错误完成状态，可重试且无重复本地记录 |
