# Domain Docs

本仓库采用 single-context 布局。

## 探索代码前

- 阅读根目录的 `GLOSSARY.md`。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策。
- 若以后出现 `GLOSSARY-MAP.md`，按其指引读取相关上下文的术语表。

上述文件不存在时，直接继续工作。
术语和决策实际明确后，由 domain-modeling 技能按需创建。

## 使用领域术语

任务标题、设计方案、调试假设和测试名称应沿用术语表中的名称。
缺少某个概念时，先核实项目现有用语；确有缺口则交由 domain-modeling 补充。

## 架构决策冲突

方案与现有 ADR 冲突时，明确指出对应 ADR 及重新讨论的理由。
